## Public demo link (PR #1, DAS-6)

A separate Vercel project runs this repo with an empty environment: no `CAL_*_URL` and no `DASHBOARD_PIN`. That deployment is demo mode by the existing `isDemoMode()` rule. It serves sample events and no PIN pad.

`README.md` links it at `https://familycalendar-demo.vercel.app` in three places: under the overview, at the top of the local demo steps, and in the License section. Each mention says the demo has an empty environment, sample events, and no PIN.

| Surface | What it says | What it must not do |
|---------|--------------|---------------------|
| README overview | Public demo link, empty environment, sample events, no PIN. A live family install is not linked. | Link a live install, a PIN, or an ICS URL. |
| README Vercel path | The live Vercel install still requires the PIN screen and is separate from the public demo. Do not put the live link in the README. | Suggest the demo project can hold real feeds. |
| README License | Repeats the public demo link and that a live install is not linked on purpose. | Claim no URL at all is linked. |

The demo project and any live Vercel project are separate projects with separate environment variables. Adding a `CAL_*_URL` to the demo project would put a family feed on a public URL. That is a Principle II violation, not a configuration choice.

## Phone kiosk shell (PR #2)

Phones were never a target size, and Phase 9 did not test them. On a phone the wall showed a black field or a sliver of type. The cause was the scale-down rule from Phase 4: `transform: scale()` shrinks the painted stage but not its layout box, so the 1180×820 box overflowed the frame, `overflow: hidden` clipped it, and `transform-origin: center center` put the visible paint outside the clip.

The fix keeps the stage at 1180×820 and wraps it.

| Viewport | Behavior |
|----------|----------|
| 1180×820, 1366×1024, 1920×1080 | Unchanged. `.kiosk-fit` and `.kiosk-stage` fill the frame at 100% × 100%. No transform. |
| Below 1180 wide or below 820 tall (container query on `.kiosk-frame`) | `.kiosk-fit` is sized to the painted result: `1180px` and `820px` times `min(100cqw / 1180px, 100cqh / 820px)`. `.kiosk-stage` sits absolutely at the top left of that box, keeps 1180×820, and scales with `transform-origin: top left`. The frame's existing centering places the fit box. Nothing is clipped. |
| Portrait and at most 900px wide (`@media (orientation: portrait) and (max-width: 900px)`) | `.kiosk-rotate-notice` covers the screen on `#0a0a0f` with a phone-rotate icon, "Rotate to landscape", and "Family Calendar is a wall display. Turn your phone sideways to view it." The notice honors `env(safe-area-inset-*)`. `.kiosk-frame` is `display: none`. |
| Landscape, at most 520px tall, and at most 1023px wide (`@media (orientation: landscape) and (max-height: 520px) and (max-width: 1023px)`) | The scale-to-fit is unreadable at that height, so `.kiosk-fit` and `.kiosk-stage` drop the transform and fill the screen at 100% × 100%. The header tightens (smaller clock, date, and temperature type; less padding and gap). The header's last column may clip instead of wrap. The day view's `.touch-pan-y` list may scroll vertically with `overscroll-behavior: contain`. |

`app/page.tsx` adds the rotate notice as a sibling of `.kiosk-frame` and the `.kiosk-fit` wrapper between `.kiosk-frame` and `.kiosk-stage`. The stage contents, `DashboardShell`, and every prop are unchanged. The page stays a Server Component.

The portrait notice and the short-landscape rules cannot match 1180×820, 1366×1024, or 1920×1080, so the gated sizes see the same layout as Phase 9. The day list scroll exists only inside the short-landscape rule. At the gated sizes the week time grid is still the only contained scroller.

Phone support is best-effort. There is no phone viewport gate in this phase.

## Today on the forecast (PR #3, DAS-21)

`WeatherWidget` shows a 3-day forecast in the header. Each day was labeled with its short weekday. The current day now reads "Today".

- `forecastDayLabel(ymd, timeZone)` compares the forecast day's `YYYY-MM-DD` with today's date in the dashboard timezone, built from `calendarDateParts(new Date(), timeZone)` in `lib/date-utils.ts`.
- A match returns `"Today"`. Anything else returns the existing `weekdayShort()` label.
- The comparison uses the dashboard timezone, not the browser's, so a wall in `America/New_York` says "Today" on the New York date.

The label is computed at render. It is not on a timer. The forecast refetches on its existing SWR interval, which re-renders the row.

## School is yellow (PR #3, DAS-22)

Demo Alex is indigo `#6366f1` and demo School was violet `#8b5cf6`. At wall distance the two read as the same calendar. School is now yellow `#eab308`.

| Place | Before | After |
|-------|--------|-------|
| `lib/demo-data.ts` School `calendarColor` | `#8b5cf6` | `#eab308` |
| `app/globals.css` `--color-cal-school` | `#8b5cf6` | `#eab308` |

The filter chip dot and the event chip border both read `calendarColor`, so both turn yellow. A live School feed still uses its own `CAL_<ID>_COLOR`. This amends the demo colors listed in `.spec/specifications/07-filter-bar.md` and `.spec/specifications/05-month-view.md`; those older specs still say `#8b5cf6` and are not rewritten.

## User Scenarios & Testing

### User Story 1 — A stranger opens the public demo from the README (Priority: P1)

Someone reading the public repo wants to see the wall without cloning it. The README links a hosted demo. It opens on sample calendars with no PIN.

**Independent Test**: Open `https://familycalendar-demo.vercel.app`. `/` loads with no redirect to `/unlock` and no "Lock dashboard" control. `GET /api/health` reports `mode: "demo"`. The README has no other deployment URL.

**Acceptance Scenarios**:

1. **Given** the README, **When** the reader looks for a demo, **Then** the overview links `https://familycalendar-demo.vercel.app` and says it has an empty environment, sample events, and no PIN.
2. **Given** the README Vercel section, **When** an operator reads it, **Then** it says the live install needs the PIN screen, is separate from the public demo, and must not be linked from the README.

### User Story 2 — A phone shows the wall instead of a black screen (Priority: P2)

Someone opens the demo on a phone. In portrait they are asked to rotate. In landscape they see the calendar.

**Independent Test**: In a phone-sized browser (for example 390×844 portrait, then 844×390 landscape), open `/` in demo mode. Portrait shows only "Rotate to landscape". Landscape shows the header, filter row, and month grid at screen size, with no document scroll. Then open 1180×820, 1366×1024, and 1920×1080 and confirm they match Phase 9.

**Acceptance Scenarios**:

1. **Given** a portrait viewport at most 900px wide, **When** `/` loads, **Then** the rotate notice covers the screen and the calendar frame is hidden.
2. **Given** a landscape viewport at most 520px tall and at most 1023px wide, **When** `/` loads, **Then** the stage fills the screen with no transform and the document does not scroll.
3. **Given** a window below 1180×820 that matches neither phone rule (for example 1024×700), **When** `/` loads, **Then** the 1180×820 stage scales down from its top left inside a fit box sized to the painted result, the frame centers it, and nothing is clipped.
4. **Given** 1180×820, 1366×1024, or 1920×1080, **When** `/` loads, **Then** the layout is identical to Phase 9.

### User Story 3 — The forecast says Today, and School stands apart (Priority: P2)

Someone glances at the wall. The first forecast day reads "Today". School events are yellow, not a second shade of Alex's indigo.

**Independent Test**: In demo mode, the forecast row's first label is "Today" and the next two are short weekday names. The School filter dot and the "School pickup" chip border are `#eab308`. Alex stays `#6366f1`.

**Acceptance Scenarios**:

1. **Given** a forecast whose first day is today in `TIMEZONE`, **When** the header renders, **Then** that label is "Today" and the other days keep `weekdayShort()`.
2. **Given** demo mode, **When** the filter row renders, **Then** School's dot is `#eab308` and its events use the same color.

### Edge Cases

- **Forecast starts tomorrow**: If Open-Meteo's first day is not today in the dashboard timezone (for example just after midnight, before a refetch), no label reads "Today". That is correct.
- **Browser timezone differs from `TIMEZONE`**: "Today" follows `TIMEZONE`, matching the clock and the calendar.
- **Tablet in portrait**: Wider than 900px in portrait (an iPad held upright) does not get the rotate notice. It gets the scaled stage.
- **Landscape phone taller than 520px or wider than 1023px**: Gets the scaled stage, not the screen-size layout.
- **Live School feed**: Uses its own `CAL_<ID>_COLOR`. Only demo data changed.

## Requirements

### Functional Requirements

- **FR-001**: `README.md` MUST link `https://familycalendar-demo.vercel.app` as the public demo and MUST describe it as an empty environment with sample events and no PIN.
- **FR-002**: `README.md` MUST NOT link a live family install.
- **FR-003**: Below 1180 wide or 820 tall, the scaled stage MUST be wrapped in a box sized to its painted size and MUST scale from the top left, so the frame does not clip it.
- **FR-004**: A portrait viewport at most 900px wide MUST show the rotate notice and hide `.kiosk-frame`.
- **FR-005**: A landscape viewport at most 520px tall and at most 1023px wide MUST show the stage at screen size with no transform.
- **FR-006**: No phone rule may change layout at 1180×820, 1366×1024, or 1920×1080.
- **FR-007**: The forecast day that equals today in `TIMEZONE` MUST be labeled "Today". Other days MUST keep the short weekday.
- **FR-008**: Demo School MUST use `#eab308` in `lib/demo-data.ts` and `--color-cal-school`.

- **SC-002**: A 390×844 portrait viewport shows the rotate notice. An 844×390 landscape viewport shows the calendar with document scroll at 0.

## Assumptions

- The public demo project's environment stays empty. This repo cannot enforce that. The operator owns it.
- Phone sizes are best-effort. A phone defect is a bug, not a regression of the gated sizes.
- `calendarDateParts` in `lib/date-utils.ts` already returns the zoned year, month, and day.

## Out of Scope (this specification)

- A phone viewport gate or a phone-specific layout beyond the rules above
- Editing the older specs' demo color lists
- A constitution amendment (tracked separately as v1.2.0; see below)
- Any change to auth, feeds, weather fetch, views, filters, or idle reset
- A Phase 10
